مشروع مشواري — نسخة تشغيل أولية مترابطة
الملفات
server.js: خادم API وقاعدة البيانات والصلاحيات.
public/index.html: تطبيق مشواري (راكب أو سائق في تطبيق واحد، بدور ثابت).
public/admin.html: برنامج الإدارة المستقل.
package.json: مكتبات التشغيل.
.env.example: أسماء متغيرات البيئة المطلوبة.
التشغيل
استخدم PostgreSQL في Supabase، وانسخ رابط الاتصال إلى DATABASE_URL.
انسخ .env.example إلى .env واملأ القيم.
أنشئ كلمة مرور إدارية مجزأة: node -e "require('bcryptjs').hash('YOUR_PASSWORD',12).then(console.log)" ضع الناتج في ADMIN_PASSWORD_HASH.
نفّذ npm install ثم npm start.
افتح / لتطبيق مشواري، و/admin.html لبرنامج الإدارة.
مهم
لا تضع كلمة مرور قاعدة البيانات أو JWT_SECRET في ملفات الواجهة.
ADMIN_PASSWORD_HASH وJWT_SECRET وDATABASE_URL تضبط في إعدادات الاستضافة كـ Environment Variables.
عند النشر، عيّن ALLOWED_ORIGINS إلى نطاق الواجهة المسموح به. إذا كانت الواجهتان تقدمان من نفس الخادم، يمكن تركه فارغاً.
هذه النسخة تنشئ جداول جديدة تبدأ بـ mesh_ ولا تحذف الجداول القديمة. لا تدمج بيانات جداول قديمة تلقائياً حتى لا يُختار دور خاطئ عند وجود رقم بطاقة في الجدولين.
إصدار رمز الراكب من الإدارة يجعل الرمز صالحاً 5 دقائق ولمرة واحدة، ويجب إبلاغه يدوياً. السائق لا يحصل على دخول قبل اعتماد الإدارة.
السعر الحالي تقديري مؤقت مبني على 5 كم، وليس حساب مسار GPS حقيقياً.
هذه نواة تشغيل مترابطة وليست اكتمال جميع متطلبات المنتج: لا تزال مطلوبة خدمات تحديد المواقع والمسارات الحقيقية، توزيع الرحلات على السائقين، تأكيدات الدفع النقدي المتبادلة، نظام المحفظة والإيداع ومراجعة الإيصالات، إدارة الموظفين وصلاحياتهم، التقييمات والشكاوى، ونسخ احتياطي ومراقبة أمنية.
لا تستخدم بيانات ركاب حقيقية قبل مراجعة سياسات Supabase والنسخ الاحتياطية واختبار النظام في بيئة تجريبية.
